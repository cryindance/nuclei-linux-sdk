#### 关键修改详解

##### 1.1 HARTID_MASK宏定义 (5d02a7a, 8eca01e)

**作用**: 添加HARTID掩码定义，限制hartid有效位数

```c
#define HARTID_MASK 0x3
```

**修改目的**:
- 在多核系统中，hartid可能包含额外信息位
- 通过掩码提取实际的core position (0-3)
- 确保在SHART(共享HART)特性下正确识别CPU核心

**影响范围**:
- 启动阶段的hartid读取
- 多核同步机制
- 中断路由逻辑

##### 1.2 PLIC处理优化 (47dac80)

**作用**: 更新optee相关配置，在sbi_init中添加调试输出

**修改目的**:
- 增强启动时的可观察性
- 便于调试多核启动问题

##### 1.3 Mailbox内存区域配置 (222d55c) ⭐重点

**修改文件**:
- `platform/generic/nuclei/customsoc.c` (+13行)
- `platform/generic/nuclei/evalsoc.c` (+26行, -1行)

**核心修改**:

在`customsoc.c`中添加了mailbox区域的非缓存配置：

```c
// 使用MATTRI0寄存器配置mailbox区域为非缓存
// 这确保CPU与外部硬件(HSM等)通过mailbox通信时数据一致性
```

在`evalsoc.c`中：
- 添加mailbox配置代码(注释形式供参考)
- 调整smpcc_base变量声明
- 重新组织缓存初始化流程

**技术背景**:
- Mailbox是CPU与HSM(硬件安全模块)通信的共享内存区域
- 必须配置为非缓存(non-cacheable)以确保数据一致性
- MATTRI(Memory Attribute Table Register Interface)用于配置内存属性

**重要性**: 🔴 **高** - 这是HSM功能正常工作的基础配置

#### 2.2 Hartid掩码统一 (riscv.h, misc.h, main.c)

**文件**:
- `core/arch/riscv/include/riscv.h`
- `core/arch/riscv/include/kernel/misc.h`
- `core/arch/riscv/plat-nuclei/main.c`

**修改详情**:

**riscv.h**:
```c
// 新增SHARTID_MASK定义
#define SHARTID_MASK 0x3

static inline unsigned long read_hartid(void) {
    unsigned long hartid;
    asm volatile("csrr %0, 0xdc0" : "=r" (hartid));
    return hartid & SHARTID_MASK;  // 应用掩码
}
```

**misc.h**:
```c
// 修改前: return read_hartid() & 0xff;
// 修改后: return read_hartid() & 0x3;
return read_hartid() & 0x3;  // 与SHARTID_MASK保持一致
```

**main.c**:
```c
// 修改前: hartid = hartid & 0xFF;
// 修改后: hartid = hartid & 0x3;
```

**修改目的**:
- 统一hartid掩码为0x3(2bit，支持4核)
- 与OpenSBI中的HARTID_MASK定义保持一致
- 确保OP-TEE和OpenSBI对hartid的解析一致
- 修复多核系统中可能的调度问题

**重要性**: 🟡 **中** - 确保多核一致性

#### 2.4 Mailbox基地址更新 (nuclei_hsm_cryp.c)

**文件**: `core/drivers/crypto/nuclei/nuclei_hsm_cryp.c`

**修改详情**:
```c
// 修改前:
#define MAILBOX_BASE (0x97000000UL)  // 在platform_config.h中定义
#define MAILBOX_SIZE (0x4000UL)
register_phys_mem(MEM_AREA_IO_SEC, NUCLEI_MAILBOX_BASE, NUCLEI_MAILBOX_SIZE);
mailbox_base = core_mmu_get_va(NUCLEI_MAILBOX_BASE, MEM_AREA_IO_SEC, NUCLEI_MAILBOX_SIZE);

// 修改后:
#define MAILBOX_BASE (0x8800000UL)   // 在驱动中直接定义
register_phys_mem(MEM_AREA_IO_SEC, MAILBOX_BASE, 0x4000);
mailbox_base = core_mmu_get_va(MAILBOX_BASE, MEM_AREA_IO_SEC, 0x1000);
```

**关键变化**:
1. **基地址变更**: 0x97000000 → 0x8800000
2. **映射大小调整**: 0x4000 → 0x1000(实际使用大小)

**技术背景**:
- Mailbox是CPU与HSM通信的共享内存
- HSM通过mailbox接收加密请求并返回结果
- 地址变更可能是为了匹配新的硬件设计或内存布局

**重要性**: 🔴 **高** - 必须正确配置才能使HSM功能工作
